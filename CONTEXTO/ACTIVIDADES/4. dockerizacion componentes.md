# Actividad 4: Containerización con Docker

## 1. Descripción y Objetivo
Empaquetar cada uno de los componentes del ecosistema en imágenes Docker livianas, seguras y optimizadas mediante `Dockerfile` independientes. Los componentes a containerizar incluyen el **Backend NestJS**, el **Microservicio de Auditoría** y el **Dashboard SSE Web**.

---

## 2. Especificación de los Dockerfiles

### 2.1. Dockerfile para Backend (NestJS)
Ubicación: `backend/Dockerfile`
Estrategia: Multi-stage build para minimizar el tamaño de la imagen final.

```dockerfile
# Stage 1: Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Runner
FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --only=production
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/prisma ./prisma

EXPOSE 3000
CMD ["node", "dist/main"]
```

### 2.2. Dockerfile para Microservicio de Auditoría
Ubicación: `audit-service/Dockerfile` (o directorio correspondiente)
Estrategia: Multi-stage build según la tecnología utilizada.

```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --only=production
COPY --from=builder /app/dist ./dist

EXPOSE 3001
CMD ["node", "dist/main"]
```

### 2.3. Dockerfile para Dashboard SSE (Web)
Ubicación: `web/Dockerfile` (o directorio correspondiente)
Estrategia: NGINX Alpine para servir archivos estáticos HTML/JS/CSS y procesar rutas de dashboard.

```dockerfile
FROM nginx:alpine
COPY . /usr/share/nginx/html
# Configuración personalizada de Nginx si se requiere soporte de fallback SPA
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

## 3. Pasos de Implementación y Validación Local

### Paso 1: Creación de `.dockerignore`
Agregar un archivo `.dockerignore` en cada componente para excluir carpetas innecesarias:
```text
node_modules
dist
.git
.env
npm-debug.log
```

### Paso 2: Construcción y Prueba de Imágenes Docker
Ejecutar los comandos de build para verificar que la compilación sea limpia y libre de errores:
```bash
# Backend NestJS
docker build -t cavalocal-backend:latest ./backend

# Microservicio de Auditoría
docker build -t cavalocal-audit:latest ./audit-service

# Dashboard Web
docker build -t cavalocal-dashboard:latest ./web
```

### Paso 3: Integración Opcional en Docker Compose (Prueba Local de Integración)
Crear un archivo `docker-compose.yml` en la raíz para probar la conectividad local entre PostgreSQL, RabbitMQ, Backend, Microservicio de Auditoría y Dashboard antes del despliegue en Kubernetes.

## 4. Criterios de Aceptación de la Actividad
- [ ] Cada servicio cuenta con su propio `Dockerfile` funcional.
- [ ] Las imágenes compilan sin errores y utilizan buenas prácticas (multi-stage, imágenes base alpine).
