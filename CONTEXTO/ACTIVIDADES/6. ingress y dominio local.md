# Actividad 6: Configuración del Ingress Controller y Dominio Local

## 1. Descripción y Objetivo
Configurar el enrutamiento de tráfico HTTP externo hacia los microservicios en Kubernetes utilizando un **NGINX Ingress Controller** y el dominio local requerido: **`conjunta3p.espe.edu.ec`**.

---

## 2. Definición del Recurso Ingress (`k8s/08-ingress.yaml`)

El manifiesto de Ingress debe definir las reglas de enrutamiento basadas en paths para el host `conjunta3p.espe.edu.ec`:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: cavalocal-ingress
  namespace: default
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /$2
    nginx.ingress.kubernetes.io/use-regex: "true"
    # Soporte para Server-Sent Events (SSE) en NGINX Ingress
    nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-buffering: "off"
spec:
  ingressClassName: nginx
  rules:
  - host conjunta3p.espe.edu.ec
    http:
      paths:
      # Ruta para la API REST y SSE del Microservicio de Auditoría
      - path: /api/audit(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: audit-service
            port:
              number: 3001

      # Ruta para el Dashboard SSE Web
      - path: /dashboard(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: dashboard-service
            port:
              number: 80

      # Ruta para el Backend Principal CavaLocal (Opcional/Centralizado)
      - path: /api(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: backend-service
            port:
              number: 3000
```

---

## 3. Configuración de Infraestructura Local y DNS

### 3.1. Habilitar Ingress Controller en Minikube / Kind
- **En Minikube:**
  ```bash
  minikube addons enable ingress
  ```
- **En Kind:** Asegurar que el clúster Kind haya sido creado con `extraPortMappings` para el puerto 80/443 y desplegar el controlador NGINX Ingress para Kind.

### 3.2. Configuración del Archivo `hosts`

Para que el sistema operativo resuelva la URL `http://conjunta3p.espe.edu.ec`, se debe asociar el nombre de dominio a la IP del nodo de Kubernetes o Minikube.

1. **Obtener la IP del Clúster:**
   ```bash
   minikube ip
   # Ejemplo de salida: 192.168.49.2
   ```

2. **Editar el Archivo `hosts`:**
   - **En Linux / macOS:** Editar `/etc/hosts` (con privilegios `sudo`).
   - **En Windows:** Editar `C:\Windows\System32\drivers\etc\hosts` (como Administrador).

3. **Agregar la entrada DNS local:**
   ```text
   192.168.49.2   conjunta3p.espe.edu.ec
   ```

---

## 4. Criterios de Aceptación de la Actividad
- [ ] El NGINX Ingress Controller está activo en el clúster.
- [ ] El archivo `hosts` redirige `conjunta3p.espe.edu.ec` a la IP de Kubernetes/Minikube.
- [ ] La URL `http://conjunta3p.espe.edu.ec/dashboard` carga correctamente la interfaz del dashboard.
- [ ] La URL `http://conjunta3p.espe.edu.ec/api/audit` responde a las consultas REST del microservicio de auditoría.
- [ ] Las conexiones SSE a través del Ingress no se cortan ni sufren buffering (configuración de headers proxy en Ingress).
