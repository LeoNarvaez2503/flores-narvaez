# Actividad 2: Desarrollo del Microservicio de Auditoría

## 1. Descripción y Objetivo
Construir un microservicio de auditoría desacoplado e independiente (desarrollado en Node.js/Express, NestJS, Go, Python u otro lenguaje) que consuma los eventos de auditoría desde RabbitMQ, los almacene en una base de datos persistente, exponga una API REST con paginación y filtros para consulta, y provea un endpoint Server-Sent Events (SSE) para la transmisión en tiempo real.

---

## 2. Especificaciones Técnicas

### 2.1. Consumo Asíncrono de RabbitMQ
- **Cola Dedicada:** Crear y vincular la cola (ej. `audit_queue`) al exchange `audit.events`.
- **ACK Manual:** Confirmar el mensaje a RabbitMQ (`channel.ack(msg)`) **únicamente después** de haberlo guardado con éxito en la base de datos de auditoría. Si ocurre un error de persistencia, rechazar o reencolar (`channel.nack(msg, false, true)`).
- **Consumo Competitivo:** Diseñado para soportar múltiples réplicas concurrentes (escenario de pods escalados en Kubernetes) sin duplicar el procesamiento de mensajes.

### 2.2. Modelo de Datos de Auditoría
Estructura de la tabla/colección `AuditLog`:
- `id`: Identificador único (UUID / Auto-increment / ObjectId).
- `entity`: Nombre de la entidad (`vinos`, `tiendas`, `usuarios`, `reservas`, `pagos`).
- `action`: Acción realizada (`CREATE`, `UPDATE`, `DELETE`).
- `userId`: ID del usuario ejecutor.
- `userEmail`: Email del usuario ejecutor.
- `timestamp`: Fecha y hora del evento.
- `data`: Objeto JSON con el estado previo y posterior (`before` / `after`).
- `createdAt`: Fecha de inserción en el microservicio.

### 2.3. Endpoints de la API REST
- **`GET /api/audit`**
  - **Parámetros de Consulta (Query Params):**
    - `page` (default: 1)
    - `limit` (default: 10, max: 100)
    - `entity` (opcional: filtra por vino, tienda, usuario, etc.)
    - `userId` (opcional: filtra por ID de usuario)
    - `action` (opcional: `CREATE`, `UPDATE`, `DELETE`)
    - `startDate` / `endDate` (opcional: filtro por rango de fechas)
  - **Respuesta Paginada:**
    ```json
    {
      "data": [ ... array de logs ... ],
      "meta": {
        "total": 150,
        "page": 1,
        "limit": 10,
        "totalPages": 15
      }
    }
    ```

### 2.4. Endpoint SSE (Server-Sent Events)
- **`GET /api/audit/stream`** (o `/api/audit/events`)
  - **Cabeceras HTTP de respuesta:**
    - `Content-Type: text/event-stream`
    - `Cache-Control: no-cache`
    - `Connection: keep-alive`
  - **Comportamiento:** Al recibir un nuevo evento válido desde RabbitMQ y ser almacenado en BD, emitir dicho evento inmediatamente a todos los clientes HTTP suscritos a este canal SSE.

## 3. Pasos de Implementación

### Paso 1: Estructuración del Proyecto
Crear la carpeta del microservicio (ej. `audit-service/`):
- Configuración de dependencias (driver de DB, cliente amqplib, framework web REST/SSE).
- Definición de variables de entorno (`PORT`, `DATABASE_URL`, `RABBITMQ_URL`).

### Paso 2: Configuración de Base de Datos y Modelos
- Definir el esquema ORM / ODM (Prisma, TypeORM, Mongoose, etc.) para la entidad `AuditLog`.
- Crear migraciones iniciales o inicializador de esquema.

### Paso 3: Consumidor de RabbitMQ con ACK Manual
- Conectar a RabbitMQ y asegurar la declaración del exchange y la cola.
- Configurar `channel.prefetch(10)` para distribución equitativa de carga entre réplicas.
- Listener del mensaje -> Parsear JSON -> Guardar en BD -> Invocar `channel.ack(msg)` -> Emitir a suscriptores SSE.

### Paso 4: Controladores API REST y SSE
- Implementar controlador GET `/api/audit` con lógica de paginación y filtros dinámicos en BD.
- Implementar controlador GET `/api/audit/stream` manteniendo una lista activa de clientes (`res.write('data: ...\n\n')`).

---

## 4. Criterios de Aceptación de la Actividad
- [ ] Consume correctamente mensajes desde la cola de RabbitMQ y los almacena en BD.
- [ ] Implementa confirmación manual de mensajes (ACK manual).
- [ ] La API REST responde en `/api/audit` con paginación y soporta filtros por entidad, usuario, acción y fechas.
- [ ] El endpoint SSE transmite los eventos en tiempo real al ser procesados.
