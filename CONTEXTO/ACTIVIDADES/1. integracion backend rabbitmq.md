# Actividad 1: Integración del Backend (NestJS) con RabbitMQ

## 1. Descripción y Objetivo
Modificar el backend principal de CavaLocal (desarrollado en NestJS) para que publique eventos estructurados en un exchange de RabbitMQ denominado `audit.events` por cada acción de escritura (**crear, actualizar, eliminar**) realizada sobre las 5 entidades principales del sistema: **Vinos, Tiendas, Usuarios, Reservas y Pagos**.

---

## 2. Requisitos Técnicos

### 2.1. Estructura Obligatoria del Mensaje (Payload)
Cada mensaje publicado en RabbitMQ debe cumplir estrictamente con la siguiente estructura JSON:

```json
{
  "entity": "vinos", 
  "action": "UPDATE",
  "userId": "usr_12345",
  "userEmail": "admin@cavalocal.com",
  "timestamp": "2026-07-29T14:30:00.000Z",
  "data": {
    "before": {
      "id": "vino_01",
      "precio": 25.50,
      "stock": 10
    },
    "after": {
      "id": "vino_01",
      "precio": 29.99,
      "stock": 8
    }
  }
}
```

*Nota: Para acciones `CREATE`, la propiedad `before` en `data` será `null`. Para acciones `DELETE`, `after` será `null`.*

### 2.2. Resiliencia y Tolerancia a Fallos
- **No Bloqueante:** Las operaciones principales de base de datos del backend NO deben fallar ni quedar bloqueadas si RabbitMQ no se encuentra disponible o presenta alta latencia.
- **Manejo de Excepciones:** Envolver las publicaciones en bloques `try/catch`, registrando errores en logs sin interrumpir la respuesta HTTP enviada al cliente.
- **Reconexión Automática:** El cliente de RabbitMQ debe intentar reconectarse automáticamente en segundo plano.

---

## 3. Guía Paso a Paso de Implementación

### Paso 1: Instalación de Dependencias
En el directorio `backend`, instalar el cliente de RabbitMQ y utilidades:
```bash
npm install amqplib @nestjs/microservices
npm install --save-dev @types/amqplib
```

### Paso 2: Creación del Módulo y Servicio AuditPublisher
Crear un módulo dedicado para la gestión de eventos de auditoría (`src/audit-publisher/`):
- `audit-publisher.module.ts`: Módulo NestJS que exporta el servicio de publicación.
- `audit-publisher.service.ts`: Servicio encargado de inicializar la conexión con RabbitMQ, declarar el exchange `audit.events` (tipo `topic` o `direct`) y exponer el método `publishAuditEvent(payload: AuditPayload)`.

```typescript
// Ejemplo de método de publicación con try-catch
async publishAuditEvent(payload: AuditPayload): Promise<void> {
  try {
    if (!this.channel) {
      this.logger.warn('Canal RabbitMQ no inicializado. Omitiendo auditoría.');
      return;
    }
    const routingKey = `audit.${payload.entity}.${payload.action.toLowerCase()}`;
    const buffer = Buffer.from(JSON.stringify(payload));
    this.channel.publish('audit.events', routingKey, buffer, { persistent: true });
  } catch (error) {
    this.logger.error(`Error publicando evento de auditoría: ${error.message}`);
  }
}
```

### Paso 3: Integración en los Servicios de las 5 Entidades
Importar `AuditPublisherModule` en los módulos correspondientes e inyectar `AuditPublisherService` en los servicios de negocio:
1. **Vinos (`VinosService`):**
   - `create()` -> Publicar evento `CREATE`.
   - `update()` -> Obtener estado previo, aplicar cambios, publicar evento `UPDATE` con `before` y `after`.
   - `delete()` -> Publicar evento `DELETE`.
2. **Tiendas (`TiendasService`):**
   - `create()`, `update()`, `delete()`.
3. **Usuarios (`UsuariosService`):**
   - `create()`, `update()`, `delete()`.
4. **Reservas (`ReservasService`):**
   - `create()`, `update()`, `delete()`.
5. **Pagos (`PagosService`):**
   - `create()`, `update()`, `delete()`.

---

## 4. Criterios de Aceptación de la Actividad
- [ ] El backend publica eventos en el exchange `audit.events` de RabbitMQ para las 5 entidades principales.
- [ ] La estructura del JSON publicado contiene exactamente `entity`, `action`, `userId`, `userEmail`, `timestamp` y `data` (con datos antes/después en actualizaciones).
- [ ] Si RabbitMQ se detiene, las solicitudes REST en el backend continúan respondiendo de manera exitosa (resiliencia verificada).
