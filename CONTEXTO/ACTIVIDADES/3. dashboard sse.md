# Actividad 3: Desarrollo del Dashboard en Tiempo Real (SSE)

## 1. Descripción y Objetivo
Desarrollar la interfaz web frontend para el Dashboard de Auditoría en Tiempo Real. Este dashboard se conecta mediante **Server-Sent Events (SSE)** al endpoint expuesto por el Microservicio de Auditoría para visualizar eventos entrantes con una latencia máxima de 2 segundos, ofreciendo filtrado interactivo y vista de detalles JSON.

---

## 2. Requisitos Funcionales y UX/UI

### 2.1. Conexión SSE y Visualización en Tiempo Real
- **Conexión `EventSource`:** Establecer la suscripción a `/api/audit/stream` (o ruta relativa detrás del Ingress `/dashboard` / `/api/audit`).
- **Actualización Automática:** Cada nuevo evento emitido por el servidor debe insertarse al inicio de la lista/tabla de auditoría sin necesidad de recargar la página (**latencia ≤ 2 segundos**).
- **Indicador de Estado:** Mostrar visualmente el estado de la conexión SSE (*Conectado*, *Reconectando*, *Desconectado*).

### 2.2. Resiliencia de la Conexión
- **Reconexión Automática:** Si la conexión SSE se interrumpe (caída temporal del pod o red), el cliente debe intentar reconectarse automáticamente con una estrategia de reintento.
- **Carga Inicial:** Al cargar el dashboard, realizar un `fetch` inicial al endpoint REST (`GET /api/audit?limit=20`) para llenar el historial reciente antes de recibir eventos en vivo.

### 2.3. Filtros Interactivos y Detalle JSON
- **Barra de Filtros:**
  - Filtrar por **Entidad** (Vinos, Tiendas, Usuarios, Reservas, Pagos).
  - Filtrar por **Acción** (CREATE, UPDATE, DELETE).
  - Filtrar por **Usuario** (Input de búsqueda por ID o email).
- **Vista de Detalle (JSON Viewer / Modal):**
  - Al hacer clic en un registro de auditoría, abrir un modal o panel lateral que formatee e higienice el JSON completo de `data` (mostrando las diferencias entre `before` y `after`).

---

## 3. Pasos de Implementación

### Paso 1: Estructuración del Proyecto Frontend
En la carpeta `web` o `dashboard/`:
- `index.html`: Estructura semántica HTML5 con contenedor de tabla/tarjetas, controles de filtro y modal de detalles.
- `index.css` / `styles.css`: Estilos modernos (UI moderna, modo oscuro/claro, badges para acciones CREATE/UPDATE/DELETE).
- `app.js` / `main.js`: Lógica de consumo de API REST, cliente EventSource y formateador JSON.

### Paso 2: Implementación de la Lógica del Cliente SSE
```javascript
let eventSource = null;

function connectSSE() {
  const sseUrl = '/api/audit/stream'; // Enrutado por Ingress o backend direct
  eventSource = new EventSource(sseUrl);

  eventSource.onopen = () => {
    updateStatusIndicator('Conectado', 'success');
  };

  eventSource.onmessage = (event) => {
    const auditData = JSON.parse(event.data);
    appendAuditEventToUI(auditData);
  };

  eventSource.onerror = (error) => {
    updateStatusIndicator('Reconectando...', 'warning');
    // EventSource reconecta automáticamente de forma predeterminada
  };
}
```

### Paso 3: Componente de Inspección de JSON
Implementar una función modal que renderice `JSON.stringify(data, null, 2)` con resaltado de sintaxis o bloques preformateados (`<pre><code>`) para facilitar la auditoría de cambios `before` vs `after`.

---

## 4. Criterios de Aceptación de la Actividad
- [ ] El dashboard muestra eventos en tiempo real recibidos vía SSE en ≤ 2 segundos desde su emisión.
- [ ] Permite filtrar eventos por entidad, acción y usuario.
- [ ] Muestra el detalle completo del JSON (`before`/`after`) al hacer clic en un registro.
- [ ] Maneja la reconexión automática ante caídas de red o reinicio del microservicio.
